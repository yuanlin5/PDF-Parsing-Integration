# PDF-Parsing-Integration

PDF 解析面板：把 PDF/图片丢进待处理文件夹，一键调用本机 MinerU 完成解析，解析结果逐项人工核对后一键归档。

## 快速开始

1. 双击 `start_panel.bat` 打开面板
2. 把 PDF/图片放进 `workspace\pending\`（可用子文件夹分项目）
3. 点「① 开始解析」，等日志出现"全部完成"
4. 在**核对区**逐项点「打开核对」：同时打开原文件与解析出的 md（md 用 **Edge** 打开，自动显示排版格式）；发现文字有误就点「编辑 md」在 **Obsidian** 里改完保存，对照无误后点「确认」
5. 全部确认后点「③ 归档」——只归档已确认的文件，未确认的留在 pending
6. 解析结果在 `workspace\output\<文件名>\`，文字内容为 `auto\<文件名>.md`，图片在 `auto\images\`

完整说明见面板内的「使用方法」区。

## 目录结构

```
├── panel.py            # 主面板（tkinter）
├── start_panel.bat     # 双击启动
├── core/
│   ├── config.py       # 路径与 MinerU 参数配置
│   ├── parser.py       # 扫描 pending + 调用 MinerU（大 PDF 自动分批）+ 归档
│   └── review.py       # 核对状态管理（待核对/已确认，落盘 review.json）
├── workspace/          # 工作数据（不入 git，启动自动创建）
│   ├── pending/        # 待处理（失败文件移入 pending\failed\）
│   ├── output/         # MinerU 解析结果
│   └── done/           # 归档：已核对确认的源文件
└── test-pdf1/          # 测试样例（1 个 PDF + 1 张图片）
```

## 核对机制（应对并行任务多）

- 每个任务（源文件）有独立的核对状态（待核对/已确认），解析与核对互不阻塞，可以解析一批、核对一批
- 核对状态持久化到 `workspace\review.json`，面板重启/关闭不丢失
- 归档只收「已确认」的任务，天然防止漏核对
- 重新解析（含勾选强制重跑）会自动重置该文件的确认状态——内容变了必须重新核对
- 核对区支持过滤（全部/待核对/已确认）与滚动列表，几十上百项也能逐项推进

## 环境要求

- **MinerU**：本机已安装（Python312，pipeline 后端，模型已下载），面板按 `core/config.py` 中的路径调用
- **Edge 浏览器**：Windows 自带，用于查看 md 的排版格式（内置 Markdown 渲染）
- **Obsidian**：md 所见即所得编辑器，用于核对时修改解析结果（首次打开 output 文件夹时按提示确认一次「作为库打开」即可）
- **Python 3.12** + `pypdf`（`pip install -r requirements.txt`）

## 注意事项

- 无独立显卡，MinerU 走 CPU pipeline 后端，解析较慢属正常现象；超过 30 页的 PDF 会自动按 15 页/批切分
- 已解析过的文件不会重复解析；如需重跑请勾选面板上的「包含已解析过的文件」
- 解析失败的文件会移入 `workspace\pending\failed\`，可移回 pending 重试
- 归档后若把文件放回 pending，会重新解析
- `test-pdf1` 里的 208MB 大 PDF 超出 GitHub 100MB 限制，未入库（保留在本地）
